# Обзор системы

## Зачем проект

Один поиск вместо разрозненных каналов. На карте видно то, что есть **в текущей области просмотра**, с фильтрами по категории, подкатегории и времени.

У **аккаунта нет постоянной роли**. Intent (`seeking` / `found` / `marking`) живёт на **объявлении**: один человек может и искать, и находить, и отмечать места. Отклик на чужое объявление открывает **чат** — отдельный блок с опциональной проверкой по примете ([08-dialogs.md](08-dialogs.md), [09-chat.md](09-chat.md)). Встреча — следующий блок ([10-meeting.md](10-meeting.md)).

Награда, QR, KYC-документы и платежи **намеренно не реализованы**. У пользователя есть только статус подтверждения личности (`none` / `pending` / `verified`), без паспорта в базе.

## Слои и каталоги

```
find/
├── cmd/api/                 # точка входа HTTP-сервера
├── internal/
│   ├── domain/              # чистые сущности и инварианты (без SQL и HTTP)
│   ├── chat/                # статусы и правила верификации чата
│   ├── meeting/             # якорь будущего блока встречи
│   ├── store/               # Postgres: миграции, seed, auth, лента, chat
│   └── httpapi/             # маршруты /api/*, cookie-сессия
├── migrations/              # SQL-файлы 001_…
├── docker-compose.yml       # Postgres 16 на 127.0.0.1:5433
└── web/                     # React-клиент
    ├── index.html           # подключает Яндекс.Карты 2.1 + React
    └── src/
        ├── map/             # страница карты и панель
        └── chat/            # UI чата и верификации
```

Связь слоёв:

```
Браузер (React)
    │  fetch /api/*  (Vite proxy → :8080)
    ▼
cmd/api  →  httpapi  →  store  →  Postgres
                │
                └── domain (валидация User, Item, Publication…)
```

`domain` не знает про БД и HTTP. `store` вызывает конструкторы `domain.New*` перед `INSERT`. `httpapi` только парсит JSON, ставит cookie и зовёт `store`.

## Порты и процессы

| Что | Адрес | Как поднимается |
|---|---|---|
| Postgres | `127.0.0.1:5433` → контейнер `:5432` | `docker compose up -d` |
| Go API | `127.0.0.1:8080` | `go run ./cmd/api` |
| Vite + React | `http://127.0.0.1:5173/` | `cd web && npm run dev` |
| Прокси `/api` | Vite → `http://127.0.0.1:8080` | `web/vite.config.ts` |

Учётные данные БД по умолчанию: пользователь `find`, пароль `find`, БД `find`.  
DSN по умолчанию в API: `postgres://find:find@127.0.0.1:5433/find?sslmode=disable`  
Переопределение: переменная окружения `DATABASE_URL`.  
Каталог миграций: `MIGRATIONS_DIR` (по умолчанию `migrations` относительно cwd).

## Главные пользовательские потоки

### 1. Открытие карты

1. Браузер грузит `index.html` → скрипт Яндекс.Карт 2.1 → `main.tsx` → `MapPage`.
2. `useYandexMap` ждёт `window.ymaps`, создаёт карту (центр Москва), слушает `boundschange`.
3. Параллельно `loadEntries()` + `loadMe()` → `/api/entries` и `/api/me`.
4. Список в левой панели фильтруется: точка внутри bounds ∩ категории ∩ подкатегории ∩ время.
5. На карту ставятся Placemark’и; клик по маркеру или строке открывает `ObjectCard`.

### 2. «Я нашел»

1. Кнопка внизу списка → панель заменяется формой.
2. Если нет cookie-сессии → регистрация или вход → `Set-Cookie: find_session=…`.
3. Форма пишет категорию/подкатегорию, название, описание, место, время; координаты берутся из **центра текущего viewport**.
4. `POST /api/found` в транзакции создаёт субъект + признаки + `publications` с `intent=found`.
5. Ответ добавляется в локальный `entries`, открывается карточка.

### 3. Фильтры

Иконка справа от «В области» **заменяет** список (список и карточка не показываются одновременно с фильтрами). Категории — дерево: отмеченная категория раскрывает свои подкатегории в том же меню. Время (`datetime-local` от/до) появляется только если среди выбранных категорий есть пропажа и/или событие; места по времени не режутся.

### 4. Профиль

Меню «Профиль» / «Войти»: регистрация, свой или чужой профиль, лента объявлений автора с фильтрами по категориям. Клик по автору на карточке открывает его профиль.

### 5. «Это моё» и чаты

1. Открыта карточка объявления с `intent = found`, автор — не вы.
2. **«Это моё»** → `POST /api/entries/{id}/claim` (нужен вход).
3. Создаётся или возвращается диалог finder ↔ claimer; открывается панель **Чаты**.
4. Переписка: `GET/POST /api/dialogs…`. Подробности — [08-dialogs.md](08-dialogs.md).

## Что пока не сделано

- Подписки (кнопка в меню без логики).
- Загрузка реальных фото (в seed — счётчик `attachments`, на UI — SVG-заглушки по `photoCount`).
- Объявление «я ищу» с формы UI (в данных/seed уже есть `seeking`).
- Сведение через таблицу `matches` (seeking+found одного субъекта) — отдельно от claim-диалога.
- Деплой, HTTPS, CORS вне Vite-proxy.
